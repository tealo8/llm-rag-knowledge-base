数据库数字只对应当前演示文档、会话/审计和瞬时 WAL 状态，不能外推生产容量。WAL 会随检查点变化，也不能当作稳定存储倍率。

本轮 8 条真实模型评估的端到端 P50 为 3421.9 ms、P95 为 15189.6 ms。该样本太小，不能估计并发吞吐或 SLA；它只说明本地私有化没有 token 账单，但长尾延迟和机器占用仍是实际成本。

## 计算方式

本地 Ollama 没有外部按 token 账单，但总拥有成本不为零：

```text
月电量(kWh) = 推理时相对空闲的平均增量功率(W) / 1000 × 月运行小时
月电费 = 月电量 × 当地分时/阶梯电价
月硬件折旧 = 设备中用于本服务的成本 × 分摊比例 / 预计使用月数
月总成本 = 电费 + 硬件折旧 + 存储/备份 + 网络 + 运维工时 + 监控与容灾
```

## 可复用测算表

下面的表格是输入模板，不是假定报价。把目标机器实测功耗、采购价、利用率和当地价格填入后即可得到月度预算：

| 成本项 | 输入 | 计算 |
| --- | --- | --- |
| 推理电费 | 平均增量功率 `P` W、运行 `H` 小时/月、电价 `R` 元/kWh | `P / 1000 * H * R` |
| 硬件折旧 | 可分摊设备价 `M` 元、使用月数 `L`、本服务占比 `U` | `M / L * U` |
| 原文存储 | 原文总量 `D` GB、备份副本 `B`、单价 `S` 元/GB/月 | `D * B * S` |
| 向量/数据库 | 实际数据库占用 `V` GB、备份副本 `Bv`、单价 `Sv` | `V * Bv * Sv` |
| 运维 | 每月工时 `T`、综合小时成本 `W` | `T * W` |
| 月度总拥有成本 | 上述各项 | 各项相加，不含一次性迁移和安全建设费用 |

### 预算边界

- `P、H、R、M、L、U、D、V、T、W` 必须由部署方提供；本项目没有这些外部输入，因此不填虚构的人民币总数。
- 备份副本、跨区容灾、对象存储、OCR、杀毒、SSO/MFA、监控和人工标注应单独列项，不能因为没有 token 账单就视为零成本。
- Qwen 模型文件大小是本机实测事实；内存、GPU、并发和电费不能由模型文件大小直接推导，必须实测或压测。

项目没有读取功率计、购机价格、当地电价、并发量或运维工资，因此不填一个看似精确但不可核实的人民币总数。应在目标机器上分别测冷启动、空闲、Embedding 和生成阶段的增量功率，再代入实际电价。

API 响应记录 `prompt_tokens`、`completion_tokens`、生成耗时和重试次数，可用于估算吞吐与机会成本。即使每 token API 费用为 0，排队延迟仍会限制单机并发。

## 容易漏算的成本

- 首次下载与版本更新的网络流量、模型磁盘和备份空间；
- 1024 维向量在当前 SQLite JSON 表示下的存储与全扫描 CPU 成本；
- OCR、病毒扫描、文档解析失败重试和人工纠错；
- 企业 SSO、审计留存、密钥轮换、监控告警和安全响应；
- 高可用副本、数据库备份恢复演练和跨区域容灾；
- 构建评估集、业务标注和模型升级回归的人力。

若改用云模型，必须在确定供应商、地区、具体模型版本、输入/输出 token 量和缓存策略后，引用供应商当日官方价格重新计算；本项目没有这些输入，不做价格预测。
