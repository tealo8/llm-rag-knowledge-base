# 评估报告（2026-08-27）

环境：本地 FastAPI `http://127.0.0.1:8080`；生成 `ollama:qwen2.5:7b`；向量 `ollama:qwen3-embedding:0.6b`，1024 维；SQLite 向量模式；数据集 8 条，4 个身份、2 个租户。运行器为每个身份先读取授权知识库，并在聊天请求中显式传入知识库 ID。报告原始 JSON 位于 `artifacts/evaluation/latest.json`。

| MRR@5 | 1.0000 |

5 条有答案用例均以 `generation_mode=model` 调用了 `ollama:qwen2.5:7b`；3 条无授权答案用例在检索后直接拒答，没有把无关文档交给模型。

本轮 P95 明显高于之前的小样本运行，最慢用例为 15189.6 ms。8 条样本不足以分解冷启动、模型排队、输入长度和系统负载的影响，但结果足以否定“本地 CPU 延迟稳定在 5 秒内”的假设。正式性能结论需要预热/冷启动分组、并发阶梯和更长时间窗口。

加载最终代码并重启服务后的独立冒烟请求耗时 20129.0 ms，仍以 `generation_mode=model` 调用 `ollama:qwen2.5:7b`，走 `hybrid` 检索，返回 1 条引用且引用接口为 HTTP 200。它不是评估集指标的一部分，但进一步说明冷启动/长尾延迟尚未达成稳定 SLA。

## 失败后改进记录

首轮真实评估的 Recall@5、MRR@5、引用有效率均为 1.0，ACL 泄漏率为 0，但拒答准确率为 0。原因是语义召回只要求余弦分数大于 0.05，导致用户看不到目标答案时，无关但已授权的文档仍成为证据。抽查余弦分数：相关片段约 `0.4595–0.7169`，无关片段约 `0.1426–0.3341`。

改进为真实向量最低相似度 `0.40`，并对 FTS 候选统一执行最小词项重合过滤。第二轮拒答准确率升至 1.0，其他指标保持不变。这个过程说明“无越权泄漏”与“正确拒答”是两个独立指标，不能互相替代。

## 结论边界

事实：本次 8 条固定用例全部满足当前断言。预测：随着真实文档和问法增加，指标大概率下降，延迟也会受模型冷启动和并发影响。判断：该结果足以证明评估链路可执行，不足以证明生产质量达标。建议由业务人员新增至少多个主题、同义改写、否定问题、冲突版本、表格数字和提示注入样本后再设上线门槛。
