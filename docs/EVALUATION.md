# 可执行评估方案

版本化数据集为 `evaluation/dataset.json`，运行器为 `evaluation/run.py`。每条数据包含身份、问题、期望文档、禁止出现的文档、拒答预期和可选答案关键词。身份是评估输入的一部分，因为同一问题在不同 ACL 下应产生不同结果。

## 指标定义

| 指标 | 本项目定义 | 当前建议门槛 |
| --- | --- | --- |
| Recall@5 | 期望文档在前 5 条引用中的比例 | >= 0.90 |
| MRR@5 | 第一份期望文档排名的倒数均值 | >= 0.80 |
| ACL 泄漏率 | 禁止文档出现在引用中的用例比例 | 必须为 0 |
| 拒答准确率 | 应拒答用例中无引用且明确拒答的比例 | >= 0.95 |
| 引用有效率 | 编号连续且当前用户可打开片段的用例比例 | >= 0.98 |
| 答案关键词准确率 | 标注关键词全部出现在回答中的用例比例 | >= 0.95 |
| 端到端 P95 | 请求耗时第 95 百分位 | 按硬件和交互目标设定 |

这些门槛是项目建议，不是行业统一事实。小数据集出现 100% 很容易，不能据此推断真实流量质量。

## 执行

```powershell
.\.venv\Scripts\python.exe evaluation\run.py `
  --base-url http://127.0.0.1:8080 `
  --output artifacts\evaluation\latest.json
```

运行器会先为每个身份获取其可访问知识库，再在请求中显式传入 `knowledge_base_id`，避免评估依赖默认知识库。每次修改分块、Embedding、阈值、融合权重、提示词或模型版本，都应保存前后报告。生产问题进入数据集前需要脱敏、去重和人工复核，且要避免从测试集反复调参造成过拟合。

## 尚未覆盖

- 8 条演示问题没有统计置信度，也不覆盖真实表达分布；
- 答案关键词不能衡量完整语义、否定关系或数字单位错误；
- 引用可打开不等于引用蕴含结论；
- 没有并发、长文档、OCR、复杂表格和百万级向量压测；
- 没有独立的红队语料与人工盲评；
- 本地模型、CPU/GPU、冷启动状态都会改变延迟。
